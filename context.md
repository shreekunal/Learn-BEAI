## 2. Learning Ground Rules
1. **Persistent Context:** Maintain `context.md` at the project root to preserve learning state, active topic, discussion notes, and roadmap across chats.
2. **Three-Tier Explanation Format:**
   - **1. Technical:** Universal, stack- and language-agnostic backend engineering. Architecture, protocol/networking mechanics (OSI layers, TCP/IP, RFC specs), data flow, serialization, security, and systems design.
   - **2. Easy Definition:** Plain English, zero fluff, intuitive explanation of what it does and why it exists.
   - **3. Real-World Analogy:** Relatable everyday analogy with clear mapping to backend components.
3. **Interactive Discussion Loop:**
   - Deep dive into one topic at a time.
   - Kunal asks counter-questions, tests edge cases, and clarifies doubts.
   - Only when satisfied, the topic is marked complete in `backend_concepts_checklist.md` and recorded in `context.md`.
4. **Terminal-Friendly Diagrams:** Terminal width is strictly constrained (137 cols max). Avoid Mermaid code blocks (which often exceed 137 cols in the CLI renderer); use clean ASCII / text box diagrams (`text` blocks) kept strictly under 80-100 columns so they render cleanly inline.
5. **Stack & Language Agnostic:** Treat all concepts as universal backend principles (applicable to Go, Rust, Java, Node.js, Python, C#, etc.). Never bias or anchor explanations to SAP/BTP specific frameworks (CAP, Approuter, XSUAA) unless Kunal explicitly asks for SAP-specific context.
